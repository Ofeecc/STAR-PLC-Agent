## 必须修复的耦合缺陷

`src/plc_agent/st_verifier.py` 的 `_detect_mapped_inputs_and_outputs` 只按同名查找观察器变量。PUB002 题目接口是 `value`，手写观察器使用 `val`，所以候选输入没有映射；编译器另声明独立的 `cand_in_value`，与 `val` 没有任何等价约束。原始反例显示 `val=0` 而 `cand_in_value=2147483648`，并因此错判上升/下降沿掩码和标志。原始模型见 `results/raw/converter_smoke_20261114/PUB002_wrong_count_probe/candidate_coupled_compile_only.smv`，诊断副本见同目录 `diagnostic_input_bound.smv`。这是自研转换器的耦合错误，不是候选 ST、VerifAPS 或题目规约错误。

在修复前应对未绑定的题目输入**直接返回 `UNSUPPORTED_ST` 或 `TOOL_ERROR`**，不可把此类结果计为候选功能反例或通过。PUB002 显式映射 `value→val` 后，还应核对类型/位宽一致性与所有输入的唯一绑定。

## 性质对应仍需审核

题库 PUB002 有 `PUB002.P_init`、`PUB002.P1`～`P6`、`PUB002.COMPLETE` 共8项；当前手写观察器是 `P1`～`P6`、`SPEC_flags`、`SPEC_init` 共8项。新验证结果的逐项 ID 全为 `SMV_1`～`SMV_8`，未与题库 ID 逐项绑定。数量同为8不等于已证明题库8条公式逐条完整下沉，特别是 `COMPLETE` 没有对应的同名性质。应引入明确的性质映射表或生成/校验机制，再允许 `candidate_st_verified=true`。

## 证据边界

此处 PUB002 候选是手写兼容性探针，位数输出固定为零，**不是 Agent 生成代码，也不是正确参考答案**。CODESYS 对该 ST 编译通过只证明语法与类型可接受。诊断副本中的手工输入绑定只用于定位原因，不属于 GitHub 正式转换器结果。
