# 六题完整流程与修复（2026-11-14）

依据 `requirements/source/Final project_ENGLISH.docx`：生成与真实 CODESYS 编译为基本环节，功能测试需要真实执行生成代码，自动功能测试和自动形式验证属于进阶功能。本轮按组内要求将二者都纳入试跑。作业整体仍要求两种框架、两种模型及全题库；本轮只是 DeepSeek + STAR 的六题预实验。

## 范围和判定

简单 PUB001/PUB003，中等 PUB007/PUB009，困难 PUB015/PUB016，共 50 个固定用例。

每题执行：重新生成 ST → CODESYS 编译/有限修复 → 冻结最终候选与源代码哈希 → CODESYS 仿真运行全部固定题库用例 → 同一最终候选转换 `.smv` → NuSMV/nuXmv 检查完整题库规约。固定测试及规范的参考实现不进入 Agent 输入；内部自测、内部辅助断言的结果与最终测评分开。

报告编译状态、固定用例通过数/计划总数、形式验证状态/性质明细，分别保留超时、不支持、工具错误及反例。仅固定测试 PASS、形式验证 PASS 且完整题库性质的对应和建模语义均满足要求时才报告完整流程 PASS。通过编译、通过 Agent 自测、参考模型通过均不能代替该判定。

## 修复

- 接口检查识别 `{attribute ...}`：只在解析端忽略属性，原始代码、哈希和 CODESYS 静态检查保持真实执行。已保存 PUB003 原候选实际编译 PASS。
- 将既有 NuSMV、nuXmv 安装放入当前工程的本地工具目录。根据模型的 SMT 特性选择检查器；工具缺失返回结构化 TOOL_ERROR，后续功能测试仍可执行。
- 仿真任务使用官方 ScriptTaskObject API 将临时项目的任务周期配置为 1 ms；记录实际时间，不修改冻结模板、不放宽题库容差。计时序列第一步也等待其声明的 dt_ms，不再硬编码观测值为 0。PUB004 原候选/原自测 2/2 用例通过实测。
- Planner 输出额度由 16384 提至 32768（本机配置），提示明确要求简短完整的计划。若仍被 length 截断，记录警告并舍弃截断计划，Coder 从完整题意继续；不进行隐藏重试。
- 失败请求按客户端请求数和响应 usage 计入消耗。没有 usage 的请求保留客户端保守预算记账，避免显示成免费请求。
- CEGAR 和自测修复同样受总编译上限约束，防止各阶段分别获得额外编译预算。
- 新增可断点续跑的六题完整流程脚本，已完成生成结果不会因重启脚本而重复调用 API。每阶段保存原始证据；原批次完整保留。
- 在六题实测中进一步修复 REAL 输入监视值的 binary32 精确回读比对、WORD 输出到整数性质观察器的数值边界转换、PUB009 明确输入/输出别名及整数编码一致性、带类型前缀的枚举字面量、CASE/数组上下界使用命名整数常量。修正之后重验同一候选及原真实轨迹，不额外调用模型。
- 为不受 nuXmv SMT 支持的整数 MOD 返回明确 UNSUPPORTED_ST，不将其伪装成模型反例。
- UI 流程日志兼容 Planner 把 state_machine 返回为列表或对象，避免真实运行记录使 `/api/runs` 崩溃。
