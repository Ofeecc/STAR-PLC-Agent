# 可执行逐拍规约检查器

本阶段实现15题：SELF001—SELF012、PUB001、PUB010、PUB011。实现位于src/plc_agent/scan_contract.py，已接入functional.evaluate_trace。只对specification_version为2.x的题库启用，历史题库继续按原口径评估。

检查器从每组用例的规定初值启动，独立读取每拍输入维护参考状态，将该拍所有实际输出与规约输出比较。它不读取生成程序内部状态，也不从错误输出更新参考状态。每组用例重新创建检查器。输出缺失也记为违反，详细结果给出scan、output、expected、observed及missing。

功能评估仍先检查真实轨迹的任务hash、代码hash、证据文件、输入与计时。随后同时检查固定expected与完整逐拍规约；任何规约违反会令该拍及该用例失败。新增scan_contract字段保存单独的规约检查结果。未支持的公共题返回UNSUPPORTED；其原有功能用例仍可评估，不能据此称其规约通过。

状态NO_VIOLATION_IN_OBSERVED_TRACE只说明本次有限轨迹未发现违反。INCOMPLETE表示空轨迹；VIOLATED含具体差异；UNSUPPORTED表示未实现该题。此模块不是通用LTL解析器，也不证明无限活性。独立调用check_contract_trace不会验证轨迹来源；只有原有evaluate_trace链路负责证据校验。

PUB001每拍最多一次阶段转移，等待保持，输出由转移后阶段唯一决定。PUB011到站当拍停车并进入等待，下一拍才能接受该站确认；手动模式清自动状态与完成灯。PUB010采用V2约定的>=5秒保护、首次>=3秒观测解除；以进入本拍前的已加热时间判定到时，所以到限同拍温度变化或故障仍可置保护，实际加热则受故障/需求抑制。计时必须提供真实观察的dt_ms，不提供时拒绝检查。该实现没有让原本不支持物理时钟的自动仿真适配器获得虚拟时钟能力。

验证结果：44项离线单元测试通过；15题现有固定期望与监控器输出一致；六组已知错误轨迹全部被可执行监控器拒绝。结果保存在results/summary/scan_contract_acceptance.json。这些都是监控器验证证据，尚未产生新的CODESYS运行证据。
