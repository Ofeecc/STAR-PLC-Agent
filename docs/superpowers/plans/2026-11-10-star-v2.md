> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor the existing PLC ST code-generation project into STAR v2 (`uv` + `git` managed, OS-agnostic) featuring a pure-Python stateless STAR harness, a fair MCP-backed baseline runner (`codex-cli` / `claude-code` / `deepseek-harness`), 32/32 simulation and random differential testing, formal verification export/import, and a lightweight WebUI auto-testing and trace inspection platform.

**Architecture:** Unpack the existing project into the repository root under `git` and `uv` management, removing `smolagents`. Isolate CODESYS project builds inside an ASCII staging directory, extend the ST test-bench generator and Python `ScanContract` oracle to all 32 tasks (including timed steps, `IN_OUT`/composite types, and seed-deterministic random differential traces), implement the artifact-centric STAR harness (Planner → Dialect Cards → Coder → Compile Repair → Independent Tester → Behavior Repair with lexicographic ratchet), expose matched `compile_st` + `simulate_st` MCP tools with server-enforced budgets to external CLI baselines (`codex-cli` / `claude-code` / `deepseek-harness`), and serve an interactive WebUI workbench via Python's standard HTTP server.

**Tech Stack:** Python >= 3.11 managed by `uv`, `git`, `unittest`, `requests`, MCP stdio JSON-RPC (`plc_agent.mcp_server`), built-in `http.server` WebUI, CODESYS V3.5 SP22 Patch 4 Scripting API.

**Spec:** `docs/superpowers/specs/2026-11-10-star-v2-design.md`

## Global Constraints

- Manage environments and execution exclusively via `uv` (`uv sync`, `uv run plc-agent ...`, `uv run python -m unittest ...`) and track all changes with `git`.
- Keep all code, configurations, CLI flags, and documentation OS-agnostic (no OS-specific labels or hardcoded drive letters; default ASCII staging uses `Path(tempfile.gettempdir()) / "plc_work"`).
- Do not use `smolagents` or any third-party agent framework for STAR; remove `smolagents` from `pyproject.toml`.
- Base models: `deepseek-v4.1-flash` (Model A) and `kimi-k3.1-pro` (Model B) via DMXAPI (`ResponsesClient`); total API budget <= 75 CNY; never invoke real model APIs without explicit user approval (`--allow-model-api`).
- Post-scan observation convention (`docs/ltl_semantics.md`): step `k` records sampled inputs `I[k]` and post-execution outputs `O[k]`.
- `agent_view(task, spec_visible)` must never expose `tests`, `test_bindings`, `specification_contract`, or `provenance` to any agent.
- Baseline (`codex_cli` / `claude_code` / `deepseek_harness`) and STAR receive the identical `agent_view`, identical tool capabilities (`compile_st` + `simulate_st`), and identical server-enforced per-task budgets (compiles <= 4, simulations <= 3, timeout <= 1500 s).

## Review Focus

- **Evaluation test or oracle leakage into agent prompt or CLI working directory:** Leaving `tests`, `test_bindings`, `specification_contract`, or `provenance` in the prompt or running an external CLI in the repository root instead of an isolated directory containing only `task_view.json` leaks hidden answers.
- **Non-ASCII path failure in CODESYS Scripting:** Passing a workspace, script, or template path containing non-ASCII characters to `CODESYS.exe --runscript` causes exit code 1 before `codesys_evidence.json` is written.
- **Unbounded or malformed agent self-tests:** Agent-supplied test cases with negative/huge `dt_ms` (e.g. `3600000`), unknown field names, or empty `steps` hang simulation or crash `build_program`, and unconstrained self-test rejection lets the Coder score 100% by rejecting every failing case.
- **`IN_OUT` caller storage overwritten across steps:** Re-initializing a `$binding` variable with `retain_storage: true` on step > 0 erases state mutated by earlier scans in `PUB017` and `PUB018`.
- **Diagnostic line-window slicing across `declaration`/`implementation` or lineless errors:** Compiler messages without a line number or with line numbers exceeding `implementation` length get dropped or raise `IndexError` during diagnostic compaction.
