# 模板库检查与 SA0027 处理建议

本次检查读取了模板副本的依赖，并对保留的 PUB003 候选进行独立编译。当前基准模板未修改，人工处理后的代码不计入 Agent 成绩。

## 库的来源与必要性

模板只有一个空的 `PLC_PRG`（实现为分号），没有直接调用设备诊断库。顶层引用如下：

| 引用 | 脚本标记 | 与本项目关系 | 建议 |
| --- | --- | --- | --- |
| Standard | 非系统引用 | 提供标准功能块等，题库需要定时器 | 保留 |
| #IoStandard | system_library=True | 设备/I/O支持，带间接依赖 | 保留设备自动管理 |
| #3SLicense | system_library=True | 当前目标自动加入的运行环境引用 | 保留 |
| #CAA Device Diagnosis，命名空间DED | system_library=True | 设备自动加入，题目与空模板未直接调用；其中名称与题目error冲突 | 保留库，对固定接口作精确例外 |
| #BreakpointLogging | system_library=True | 调试/断点支持的自动引用 | 保留设备自动管理 |

`system_library=True` 按官方脚本API表示由插件隐式加入。这能确认来源，不能证明所有运行方式都必须使用它。就本题算法而言，CAA诊断接口没有被调用；就现有Control Win模板而言，不建议删除设备管理的引用或卸载库。若以后制作最小模板，需单独版本化并重新做编译/仿真预检。

实际递归清单：`results/raw/library_audit_87bebead7734/libraries.json`。原模板哈希始终未变：`70d40be7b4b9bdf4a22619a7ba47156422cf6beaec692480f0e5ee2acbda8909`。

## 已验证的修改方案

只把CAA诊断库的 `qualified_only` 改TRUE，PUB003仍报SA0027，该方案无效。证据：`results/raw/library_audit_bef305be8a02/qualification_probe.json`。

推荐保留固定接口名，只对该变量声明添加例外：

```iecst
VAR_OUTPUT
    hiAlarm : BOOL;
    loAlarm : BOOL;
    // Official task interface; intentional device-library name collision.
    {attribute 'analysis' := '-27'}
    error : BOOL;
    status : WORD;
END_VAR
```

实测带注解的PUB003保留代码编译PASS；另加未使用变量并通过任务调用，SA0033仍报错、编译验收COMPILE_FAIL。局部例外没有关闭全部静态检查。证据：`results/raw/name_exception_2026-11-11T013259952465+0000/summary.json`，`verified=true`。

该注解目前只用于验证副本，尚未自动注入正式Agent链路。正式接入建议：

1. 编译适配层维护“强制接口名+已确认库冲突”白名单，先覆盖PUB003的error；PUB009/PUB017等同名接口另行验证，不任意豁免内部变量。
2. 保存Agent原始代码、适配后代码、变更原因与各自哈希；编译和仿真使用同一适配结果。原始代码规范性与适配后可编译性分开记录。
3. 自研和后续基线使用相同环境及适配政策。先识别环境约束，避免模型反复修改不可变题目接口。
4. 保留其他SA0027诊断及所有其他规则，不推荐全局关闭SA0027，也不推荐修改题目接口。

官方依据：[SA0027定义](https://content.helpme-codesys.com/en/CODESYS%20Static%20Analysis/_san_rule_sa0027.html)、[库引用脚本API](https://content.helpme-codesys.com/en/ScriptingEngine/ScriptLibManObject.html)、[Static Analysis Light配置](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_dlg_project_settings_stat_analysis_light.html)、[局部analysis属性语法](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_using_static_analysis.html)。

## 新的角色输出限制

历史中Planner用到过6993输出token，Tester曾耗尽8192，PUB003修复也耗尽8192且全部用于思考。因此按角色放宽，保留异常兜底；上限不是目标消耗。

| 角色 | 单次最大输出token |
| --- | --- |
| Planner | 16,384 |
| Coder | 24,576 |
| 编译修复/行为修复 | 32,768 |
| Tester | 24,576 |
| 未指定角色请求 | 24,576 |

已写入 `configs/runtime.json`、本机私有配置及 `configs/pilot_pair.json`。pilot仍请求high思考强度。输出上限包括服务计入输出的reasoning token，并非只限制最终代码。

配套设置：本地上下文预算131,072；单次420秒；单题2400秒；每题最多9次请求；pilot候选编译最多3次，自测范围仍为2例、每例最多8步。一起放宽上下文，避免提高输出后仍被原32K本地门槛拦截。

新增单题累计token安全阈值300,000。下一请求前检查“已计用量+下一完整输入的保守计数+预留输出”，超限直接停止，不删历史、不自动加额度或重试。失败/截断响应也按usage累计；缺少总用量时保留整次保守预留，避免把失败当免费。`token_budget_accounted`日志记录计账来源。请求次数、超时和编译次数独立生效。

131,072是本地计数预算，不改变服务模型窗口；UTF-8字节加256的计数代理不是服务tokenizer。新上限尚未付费试跑，后续获批实验须确认服务接受参数及实际usage。更宽上限降低正常截断概率，不能保证任何任务都必然完成；若再次截断仍留痕停止，不自动扩大预算。
