# 批量测试使用说明

新增入口 `scripts/run-batch.ps1`，底层为 `scripts/run_batch.py` / `plc_agent.batch`。在项目根目录打开 PowerShell 运行下列命令。

## 常用命令

重新测试现有六题代码，执行编译证据核查、真实 CODESYS 固定测试和 ST→SMV→模型检查：

```powershell
.\scripts\run-batch.ps1 -Tasks pilot -Workers 2 -OutDir results/raw/my_pilot_batch
```

默认读取 `results/raw/six_task_fullflow_20261114/<题号>/generation/result.json` 和选中的 `final_candidate.json`。成功的原编译记录只有在原始 CODESYS 证据、请求 ID、源代码哈希及进程退出码核查通过时才复用；否则重新编译。固定用例默认重新在 CODESYS 仿真运行，不使用 Agent 自测代替。

换为指定题号和其他候选记录目录：

```powershell
.\scripts\run-batch.ps1 -Tasks PUB001,PUB003 -SourceDir results/raw/another_campaign -OutDir results/raw/my_pair_batch
```

`-Tasks` 支持 `pilot`（2 简单、2 中等、2 困难）、`public`、`self`、`all` 和英文逗号分隔的题号。候选目录支持 `<题号>/generation/result.json` 或 `<题号>/result.json`；记录必须与当前题库哈希和模型名称一致。默认模型为 `deepseek-v4.1-flash-1017`，其他模型可用 Python 入口的 `--model` 指定。

先查看全题库计划，不执行编译、仿真、形式检查和模型请求：

```powershell
.\scripts\run-batch.ps1 -Tasks all -DryRun -OutDir results/raw/all_plan
```

只回归转换器与形式检查，复用原编译证据和真实轨迹：

```powershell
.\scripts\run-batch.ps1 -Tasks pilot -ReuseTraces -OutDir results/raw/recheck_batch
```

`-ReuseTraces` 明确标记为“真实轨迹回放”，检查题目、源代码哈希与支持证据，不能计为本次重新仿真。只想运行某些阶段时可用 `-Stages functional,formal` 或 `-Stages formal`；未执行阶段保持 NOT_RUN，不会凭空补成完整流程通过。

要重新独立编译候选，可加 `-Recompile`。默认每题全部固定用例合并到一次仿真任务；各用例拥有独立 FB 实例。

## 断点续跑与故障处理

- 重复**同一条命令、同一个 `-OutDir`**，会复用已完成阶段，不重复生成、不重新启动已完成的仿真或求解器。每个阶段在完成时立即落盘。
- `-RetryInfra` 重跑已保存的 TOOL_ERROR/TIMEOUT/UNVERIFIED 等基础设施结果，旧尝试目录保留。它不会自动重新请求模型生成代码。
- 题库、候选、转换器代码或运行配置变化后，使用新的 `-OutDir`。输入指纹不符时脚本拒绝把旧结果当作新结果。
- 基础设施故障默认停止派发后续题；已经派发的最多两个任务会完成当前工作。程序测试失败、反例、明确的不支持转换不会被当成基础设施中断。需要收集所有可用结果时加 `-KeepGoing`。
- 在输出目录创建名为 `STOP` 的文件，可停止派发并让工作进程在下一阶段前停止；当前 IDE 操作会先结束。移除 STOP 后，用原命令继续。
- 意外中断的编译、仿真和形式检查下次写入新的 `attempt_0002` 等目录。**生成中断且未写出结果**时不自动重新付费生成，需要先人工检查生成日志。
- 同一输出目录有进程锁，禁止两个批次同时写入。同一台电脑的编译与仿真共享 IDE 锁，避免互相争用。

## 速度策略和边界

默认两个独立任务进程。模型等待、形式检查可与其他题目的编译/仿真重叠；CODESYS 仍保持一个通道，以免 Gateway、仓库及在线应用发生冲突。可设置 `-Workers 1` 做顺序对照，通常先使用 2；增加进程数不会让 IDE 同时运行多个仿真。

每题仍使用独立的临时 CODESYS 工程，本轮没有使用未经验证的常驻 IDE 会话。断点复用与轨迹回放省去的是已完成工作，不能与重新生成、重新仿真的总耗时混为一谈。

## 生成缺失代码时的授权

默认不创建模型客户端，不生成缺失题目。没有候选时会报告 MISSING_CANDIDATE；`-Tasks all` 不意味着自动付费生成所有题。

按已有组内要求，**每次真实模型实验均须先获得负责人明确批准**。批准某一批次后，才在命令中使用：

```powershell
.\scripts\run-batch.ps1 -Tasks all -SourceDir results/raw/source_campaign -OutDir results/raw/new_full_campaign -Workers 2 -GenerateMissing -AllowModelApi
```

标志用于记录批准，不能代替批准。只为缺少生成记录的题调用 STAR/E3，已有记录不会静默重试。模型参数沿用 `configs/runtime.local.json`，每题限额保持生效；两个任务并发时会分别消耗各自的限额。API Key 不进入执行计划或 manifest。

## 结果位置与解释

输出目录包含：

- `plan.json`、`manifest.json`：题目选择、并发数、源目录、配置和输入指纹。
- `summary.md` / `summary.csv` / `summary.json`：完成数量、测试通过数和各题结果，随任务完成更新。
- `invocations/<本次运行ID>/summary.json`：每次执行单独保留汇总，重复命令不会覆盖前次批次的耗时记录。
- `events.jsonl`：任务完成事件；每题 `progress.json`：当前阶段与工作进程 PID。
- 每题 `candidate.json`、`compile.json`、`functional.json`、`formal.json`、`fullflow_result.json`。
- 阶段尝试目录中的原始编译日志、真实轨迹、SMV 模型及求解器结果。`mode` 区分原编译证据复用、重新编译、重新仿真和真实轨迹回放，`cached` 区分断点复用。

PASS 的最终条件仍是编译通过、固定测试通过，且形式结果明确满足 `full_specification_verified`。只通过转换后部分性质时保持 PARTIAL；当前六题已有的形式覆盖缺口不会因批量执行而消失。退出码：0 为批次完成（可含 PARTIAL/UNSUPPORTED_ST）；1 为存在代码编译失败、测试失败或反例；2 为基础设施阻塞、缺少候选或停止。

## Python 环境

PowerShell 优先使用项目 `.venv`，其次使用本机忽略文件 `.local/batch_python.txt` 记录的解释器路径，最后使用 PATH 中的 Python。可用 `-Python '完整 python.exe 路径'` 显式选择。队友应使用自己的 Python 3.11+ 环境并安装项目依赖；本机路径无需分享。

也可以直接使用 Python 入口，无需设置 PYTHONPATH：

```powershell
python scripts/run_batch.py --tasks pilot --workers 2 --out-dir results/raw/my_pilot_batch
```

Windows 真实 CODESYS 操作应在正常终端执行；由 Codex 调用时走已批准的沙箱外执行机制，避免已确认的 APInstaller 沙箱权限故障。

## 四组完整实验入口

负责人随后要求验证后直接开跑、准备本地 Codex CLI 对照、另一模型使用 GPT-6.1-terra，共四组。新增 configs/fullflow_matrix.json 与 scripts/run_fullflow_matrix.py；按两个框架 × 两个模型安排，每组 32 题、276 条固定用例。

| 组别 | 框架 | 请求模型 ID |
|---|---|---|
| E1 | 本地原版 Codex CLI | deepseek-v4.1-flash-1017 |
| E2 | 本地原版 Codex CLI | gpt-6.1-terra |
| E3 | STAR | deepseek-v4.1-flash-1017 |
| E4 | STAR | gpt-6.1-terra |

该矩阵与早期 experiments.json 中的 custom_tool_loop / Kimi 实验分别保存，不能把旧记录改名当作本次 Codex 或 GPT 对照。请求模型 ID 来自已有中转目录，不单独证明底层模型身份。

只形成计划与汇总：

    python scripts/run_fullflow_matrix.py

本次会话已获得负责人直接执行的授权，使用以下命令执行；后续新实验仍需先获对应授权：

    python scripts/run_fullflow_matrix.py --run --allow-model-api

四组总表位于 results/raw/four_group_20261114/matrix_summary.md 及同名 JSON。每组独立目录；顺序执行各组，组内两个任务进程、一个共享 IDE 通道。运行器冻结源代码，避免准备对照入口时改变正在执行的组。STAR＋DeepSeek 已完成题采用明确的结果引用，retained_results 列明来源；未执行题才排队生成，避免重复付费及重复正确的仿真。

单独运行 Codex 组也支持（此命令付费，须已获对应实验批准）：

    .\scripts\run-batch.ps1 -Driver codex_cli -Model gpt-6.1-terra -Condition E2 -Tasks pilot -SourceDir results/raw/empty_sources -OutDir results/raw/codex_terra_example -GenerateMissing -AllowModelApi

原版 Codex 决定上下文与工具调用，PLC MCP 服务只提供有配额的编译、自测和形式检查。没有把 STAR 的控制流程套给 Codex，也不再以 custom_tool_loop 代替现成 Agent。Windows npm 包优先调用其中的原生 codex.exe，本机已核对版本 0.142.5。

Codex 外接本地 Responses 转发器，仅负责同一模型路由、high 强度、上下文/输出/请求/总 token 安全限额和请求响应留档。它不生成提示计划、选工具或改代码。CLI 只获得临时本地凭据，教师 Key 保留在转发器内。转发器差异写入各题 invocation；不能宣称两种框架内部请求完全相同。配置方法参考 OpenAI 官方 [MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

每题保存生成过程、完整上下文、CODESYS 原始证据、固定测试轨迹、候选哈希与形式结果。Codex 请求响应位于 generation/api_transport/request_*/，过程事件位于 generation/events.jsonl。不额外付费做兼容性探针，首批真实题同时承担接入检查；基础设施故障会停止后续组，保留诊断。

费用监测支持带人民币符号的 cost 字符串，避免重复累计汇总 usage。设 75 元返回费用停止阈值，触发后不再派发；在途请求可能仍产生费用。该数包括本轮六题和矩阵目录内请求，不是平台余额，也不涵盖更早全部课程消耗。缺失费用字段单独统计，不能当作免费。

## 长时与精确时序用例

全题库实际执行发现 PUB004.T3/T5 含近 500 小时的真实间隔，不能压缩成几秒后仍声称原测试通过。新入口在启动 IDE 前排除超出任务物理时间预算的用例，列明 unsupported_wall_time_cases，保留完整计划分母，其余用例继续；后续覆盖这些用例需要单独验证虚拟时钟。

原库还有 dt_tolerance_ms=0 的精确时序用例。Windows 仿真可能出现 1～几毫秒抖动，时序不符时标为 TIMING_NOT_REPRODUCED，不计通过，也不据此判代码错误；有效的其他用例仍能判定。没有放宽原定容差。原始轨迹保持不变，报告分别列出通过数、时序有效执行数、全部计划数。

扫描器现为同一扫描只采样一次时间，减少重复 TIME() 取值造成的误差；仍未替换真实 PLC 时钟。TIME/LTIME 输入按 IEC 时长精确比较，避免 TIME#2s 与 T#2000ms 的显示差异导致输入不匹配；相差 1ms 仍不相等。
