## APInstaller.CLI 反复弹窗

这次弹窗由自动化测试在受限进程环境中启动 CODESYS 触发。安装组件试图写 Windows 事件日志时收到拒绝访问，抛出未处理异常：

```text
System.AggregateException: An error occurred while writing to logger(s).
Cannot open log for source 'AP Installer'. You may not have write access.
System.ComponentModel.Win32Exception (5): 拒绝访问。
```

对照结果：同一 `APInstaller.CLI.exe --help` 在受限环境退出 1，并输出上述堆栈；通过工具批准机制在普通 Windows 进程环境运行时退出 0，正常输出帮助。受限环境的仿真同时存在 Gateway 连接失败。

修复方式是改变真实 CODESYS 测试的启动环境。Python 单元测试仍在沙盒内执行；真实 CODESYS 编译、仿真改在普通 Windows 进程中执行。要求已写入项目 `AGENTS.md`。普通 PowerShell 中手动执行项目脚本也属于普通进程环境。不需要给脚本添加管理员权限。

没有修改安装目录、注册表权限或系统日志设置。诊断时曾仅对子进程临时关闭 EventLog 日志提供器以确认故障位置；最终成功验收没有使用该设置。最终两轮真实执行的日志不含 APInstaller 未处理异常，桌面窗口清单中也没有该错误窗口。

## 代码修复

- 形式验证导入不再将 `UNVERIFIED`、SAT、UNSAT 或孤立的 true 字样误认为完整证明。只有编码完成、工具匹配、源码与题目哈希匹配、逐属性结果完整且全部通过的证据才能标记 verified。当前导出仍是待编码材料，不宣称已实现完整模型检测。
- 修正自测用例集合变化后，Ratchet 比较不同集合分数而返回旧候选的问题；记录候选与用例哈希。固定评测覆盖率与 Agent 自测结果分开保存。
- 编译、仿真基础设施错误会停止相应修复流程，不再引导模型为工具错误修改代码；仿真覆盖不完整保持 UNVERIFIED。
- CLI 默认优先读取 `runtime.local.json`；增加实际安装路径识别，支持 `.profile.xml`；Windows 标准输出使用 UTF-8。
- WebUI 缺少 CODESYS 时返回 UNVERIFIED，不再自动使用 FakeBackend 给任意代码判通过；保留真实执行证据目录，兼容实际轨迹格式；没有观测值的波形不再用期望值补造。
- 随机用例只生成输入和期望值，不把 oracle 输出当作候选程序实际输出。
- 修正 Windows 验收脚本的失败退出行为；真实参考验收显式选择 CODESYS。
- 明确当前 baseline 是自写工具调用循环。历史统计独立保存在 `historical_readme_results.md`，未将它们当成本次 STAR v2 实验结果。
- 真实模型命令要求 `--allow-model-api`。该标志仅记录已取得的本轮授权，不能代替使用前向用户请示。
