# STAR-PLC-Agent 偶数题审查汇总

**审查基线** `main` 提交 `a162fea`，题库规约版本 `2.1-normalized-20261111`。本稿汇总两份审查及交叉复核结果，覆盖 10 道公开题和 6 道自建题。

## 总体结论

- **16 道题、116 条规约、53 组固定用例、346 拍。** 离线逐拍重放后，`expected` 中的 **1,018 项显式顶层断言**均与当前参考定义一致。`PUB012`、`PUB016`、`PUB018`、`PUB020` 共 **102 拍**只列出部分输出，合计省略 **164 项字段断言**。评测器可以用逐拍参考规则补查实际采集到的字段。 [评测入口](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/src/plc_agent/functional.py#L95-L120)
- **已复现 9 项漏测。** 按组友报告提出的方向，独立构造的九种错误行为均能通过各自原有固定轨迹，加入针对性输入后才出现输出差异。六道自建题另复现了 **552 条参考状态转移**，所选属性通过。`SELF008` 在这项枚举中取 `Preset=0…6`。 [可达状态探索脚本](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/scripts/check_reference.py)
- 仓库记录 **170 项 Python 单元及业务测试**和 **1 项 Windows 回环 HTTP 集成测试**通过。交叉复核重跑了题库参考检查和状态探索。CODESYS 结果的证据状态见下文。 [仓库测试记录](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/results/summary/specification_normalization_tests_20261111.txt)

## 提交前优先处理

1. **统一定时题的采样与评分。** `PUB004`、`PUB006`、`PUB010`、`PUB012` 都可复现同一问题。偏差 1 ms 的样本可进入默认 ±25 ms 容差，却可能跨过行为阈值。评分同时比对标称 `expected` 和按实测时间重算的结果，两者可能要求不同输出。精确边界用例应使用可控时钟或精确采样。允许抖动时，先确认实测轨迹命中预定分支，再用一致的时间口径评分。另需修正显式零容差也被当成默认 ±25 ms 的分支。 [评分代码](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/src/plc_agent/functional.py#L99-L117)
2. **让 PUB008 的不同下界真正进入测试。** JSON 登记了不同数组下界，当前包装器却把两者都声明为从 1 开始。生成声明、赋值和读回应分别使用各自的下界，再补两种数组长度关系及只读字段检查。同步统一用例容差和 REAL 换算可表示域。 [数组绑定生成](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/src/plc_agent/simulation.py#L216-L224)
3. **补齐 PUB018 参考 ST 的 FIFO 行为。** 源码只更新元素计数和状态。补上调用方缓冲区的入队写入、出队读回及回绕，并确认可用的泛型绑定。保留两种现有绑定，另测容量 1，补齐成功状态和 B 绑定最后一个元素的回读。 [参考 ST](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/codesys/examples/PUB018.json)
4. **补运输中间拍，修正 PUB020 到位谓词。** `PUB016` 和 `PUB020` 的固定用例都能放过只在发车拍动作的实现。应在发车后、目标到位前插入一拍，断言电机持续运行。`PUB020` 的到位判定应明确使用拍前运输阶段和对应目标传感器，统一 `P4/P8/P9` 的状态和事件定义。 [PUB016](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/dataset/public/PUB016.json) · [PUB020](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/dataset/public/PUB020.json#L148)
5. **确认原题边界，再同步规约和测试。** `PUB004` 与 `PUB012` 要确认 `CycleTime` 是否应等于采样间隔，以及运行时间计入哪一拍。`PUB010` 要确认原文「超过 5 秒」与现行「达到 5 秒」的口径。`PUB014` 要确认 15 字符是否是有效地址的硬限制，当前有用例接受带前导零的 107 字符地址。 [老师原题库](https://github.com/Ofeecc/STAR-PLC-Agent/blob/a162fea2f7001e179a700bc8b7ad47200cd288e7/requirements/source/public_bank_original.json)

**统一修改时还要处理四件事：**

1. **把重要行为展开为可单独审核的公式。** `CompleteBehaviorV2` 已有参考转移定义，但不能让大量关键要求只藏在总谓词里。
2. **让 Agent 实际收到自包含的规约。** 不能在输入中引用它看不到的辅助状态或定义，也不能因此把参考答案和测试答案直接提供给它。
3. **统一自建题的题面格式。** 按“背景→编号功能要求→接口→初值→扫描与计时约定”整理，中英文同步；LeadA、门禁等规则直接写清楚。
4. **同步测试、中文 UI 和版本绑定。** 每条用例说明验证什么，每拍尽量列全受约束输出；更新后再检查 NuSMV 接受性及参考一致性。
