## 2. 本地 NuSMV 检查器

已从官方站点安装 NuSMV 2.7.1 Windows 64位版本，校验官方 SHA256。安装位置 `.local/model_checkers` 不进入 Git。其他组员运行 `scripts/install_nusmv.ps1`，或配置环境变量 `NUSMV_EXE` 指向自己的可执行文件。

在项目虚拟环境安装了本项目后，从仓库根目录运行：

```powershell
plc-agent check-model --model models/PUB001_reference.smv --out-dir results/raw/my_model_check
plc-agent check-model --model models/negative_control.smv --out-dir results/raw/my_negative_check
```

也可用 `python -m plc_agent.cli` 替换 `plc-agent`。未安装包时先令 `$env:PYTHONPATH = Join-Path (Get-Location) 'src'`。

网页中切换到 PUB001，在规约审核说明中点击“NuSMV：检查 PUB001 参考模型”。入口只运行仓库自带模型，结果日志保存在 `.local/model_checker_evidence`，不调用语言模型。

结果文件：`model.smv`（被检查内容）、`stdout.txt`（含反例）、`stderr.txt`、`model_check_result.json`（状态、性质结果、文件哈希等）。所有声明的性质均有结果且成立才返回 `MODEL_PROPERTIES_TRUE`；发现不成立返回 `COUNTEREXAMPLE`；进程错误、缺少性质结果、语法错误和超时不会算通过。CLI 对反例及工具错误返回非零退出码，属于预期行为。

本机验证证据：`results/raw/model_checker_20261110`。

### 覆盖范围与后续工作

- 这是可用的 SMV 检查后端，并非 ST 自动翻译器。模型输入是显式编码的 `.smv`，不能把 `.st` 改后缀运行。
- PUB001 模型用扫描前 phase 和本拍结束输出表达 P2–P10；输入是不加公平性约束的非确定布尔量，进度性质自身带环境前提。
- P1 检查的是第一次执行前的实例初值，这与模型中的扫描观察点不同，没有混入上述9条结果。`CompleteBehaviorV2` 也没有单独转化为检查性质。
- 当前没有证明该手写参考模型与 Agent 生成 ST 等价，结果字段 `candidate_st_verified=false`。因此这些结果不能计入 Agent 代码形式验证成功率。
- 其余五题还需要 REAL 数值抽象、历史窗口、时间、边沿与数组等模型编码及与代码的对应关系。模型编码审查、候选代码映射及验证、功能测试仍需继续。

官方下载与许可证信息：https://nusmv.fbk.eu/downloads.html 。安装脚本下载官方二进制，不将其作为自研框架代码。

## 3. 人工审核规约

网页六题共53条属性均有中文含义和审核提示，公式按层级给括号配色，逻辑连接处换行，鼠标悬停可高亮配对括号；可展开原始公式与原英文说明。中文说明绑定当前公式，公式变化后页面提示重新审核。

以 PUB001.P3 为例：

```text
G(
  (phase=0 & bottleSensor)
  -> (Pump_Motor & X(phase=1))
)
```

读成：每一拍，只要扫描开始空闲且检测到瓶子，本拍结束清洗泵必须打开，下拍开始的阶段必须为清洗。X 只作用于括号内的阶段；不能把泵启动也推迟一拍。

审核时写出：老师原文依据、组内补充约定、应通过的轨迹、应失败的轨迹、对应测试ID。推荐检查：phase=0、有瓶、本拍泵开启且下拍进入1应通过；有瓶却不开泵应失败；没有瓶时该蕴含式不约束泵，必须结合完整行为禁止无瓶启动。P3 独自无法代替完整规约。

符号：G 始终，F 最终但不保证期限，X 下一拍，! 非，& 且，| 或，-> 蕴含，<-> 当且仅当。`init` 是初值条件，不能随意加 G；`oneHotOutputs` 在此为“至多一个输出为真”。中文逐条审核表见 `六题规约中文审核.md`。
