# Dataset contract version 1

Each UTF-8 task JSON has `schema_version: 1`, `id` (PUB001..PUB020 or SELF001..), `kind` (`public` or `self_built`), `title`, `difficulty` (`easy`, `medium`, `hard`), `provenance` (object with `source_type`, `source_file`, `source_index`, `adaptation`, `rationale`, `review`), `requirements` (full English text), `scenario`, `interface` (list of objects with `direction` INPUT/OUTPUT/IN_OUT, `name`, `type`, `description`), `initial_conditions` (object), `scan_semantics` (string), `safety_priority` (list), `assumptions` (list), `ltl` (list of `id`, `formula`, `explanation`), `atomic_propositions` (object defining every abbreviation), `tests` (list of `id`, `purpose`, `steps`, optional `notes`). Each step has complete `inputs` and partial `expected` output mappings; omitted expected outputs are unconstrained. Each test resets the FB instance. Record TIME/LTIME values as IEC literals such as T#100ms. Use `dt_ms` per step for physical elapsed-time requirements. Composite data are JSON lists/objects. No test outputs are actual PLC execution results.

Default scan convention: state s[k] contains sampled input I[k], pre-scan retained state q[k], and end-of-scan output O[k]; q[k+1] is updated state. Same-scan safety uses G(stop -> !run); next-state retention uses X. The initial instance is reset before step 0; step 0 itself executes normally. Explicit task-specific timing assumptions override this default and must be recorded. Finite tests do not prove unbounded LTL liveness.

Public source text must be preserved verbatim in `requirements`, with any interpretation separated into `assumptions`. Self-built tasks must be independently constructed and include a transparent synthesis/review record. Task tests and Python oracles are expected values, never CODESYS execution evidence.

## Specification normalization 2.1 (2026-11-11)

`normalized_specification` defines `I[k]` (sampled caller input), `O[k]` (independently observed candidate output), `Sref[k]` (independent reference state before the scan), constructor state, observed initial constraints, history bindings, finite-conjunction domains, comparison policy and pinned transition sources. Initial-instance checks occur BEFORE the first invocation and must not be inferred from `O[0]`. Unlisted initial observed fields are unconstrained by this initial predicate; reference constructor state is fully specified separately.

`CompleteBehavior[k]` is the Boolean relation between actual constrained output fields and the expected values of the pinned input-driven transition. Candidate outputs never update the independent reference. Previous ACTUAL output memories are a separate observer state, initialized as declared. Candidate-internal variables need not have names matching reference/ghost states.

Unified naming convention (`normalized-20261114`): all test IDs are `<TASK_ID>.T1..<TASK_ID>.Tn` (with any descriptive slug retained in `name`), and all LTL IDs are `<TASK_ID>.P_init` (pre-invocation initial snapshot when present), `<TASK_ID>.P1..<TASK_ID>.Pn`, and `<TASK_ID>.COMPLETE` (`G(CompleteBehavior)`). The active transition snapshot lives under `dataset/specifications/normalized_transition/`.

The active language is **LTL over typed scan predicates**, not a completed native NuSMV encoding. `X` takes a Boolean formula. DWORD input-memory transport is expanded into 32 Boolean bit equivalences. Array conjunctions have explicit ordinal bounds; empty conjunction is TRUE. Binding length and processed `count` are distinct. Timed liveness clauses include `G(F(TimeTick))`, requiring infinitely many new integer-ms boundary crossings; positive time increments alone do not exclude Zeno input traces.

Integers and Booleans compare exactly including type. Finite floating expected results use absolute tolerance 1e-5; PUB008 only grants relative tolerance 2e-6 to successful converted outputValue, retaining exact comparisons for preserved/configuration data. Time values compare as integer nanoseconds. PUB017 successful deletion does not constrain that slot's non-ID fields on the deletion scan; later no-write invocations preserve their actual sampled representation. PUB018 does not constrain a physical circular-buffer layout, but constrains count/status/item and the input-history FIFO behavior over all scans.

`NormalizedScanMonitor` evaluates only the complete scan predicate on finite observations; it does not interpret ST, execute all focused LTL clauses, authenticate observations, establish liveness, or prove infinite-trace properties. The historical 244 entries remain material count, including initial constraints and composite predicates, not 244 proven native-LTL properties. All human review and candidate formal verification remain pending.

Definitions are archived under `dataset_versions/before_normalization_20261111/`; fixed transition snapshots are under `dataset/specifications/normalized_transition_v1/`. Never overwrite a released transition snapshot: change the definition version and update its hashes explicitly. Existing raw experiment records retain their original task hashes and meanings.
